“Target Architecture v1” complète

APRES LA CAPACIBILITY MAP

C’est fait. La Target Architecture V1 complète est maintenant formalisée comme document de référence.

Télécharger — TARGET ARCHITECTURE V1 — AGENCY

Ce que cette V1 verrouille

10 grandes branches : Core, Project, Tools, Work, Quality, Observability, Governance, Knowledge, Export, Adapters.

La séparation Agence / produit Maison IA.

Les frontières Application → Domain → Ports → Adapters.

Les contrats fondamentaux : ModelGateway, Repository, Tool, Task, Process, Finding, Report, ExportManifest.

La distinction stricte Tool ≠ Agent, Task ≠ Workflow ≠ Process ≠ Execution, Rule ≠ Check ≠ Evaluation ≠ Judgment.

La nouvelle architecture du Tool System autour de Registry → Broker → Runtime → Usage → Learning.

La future architecture du Work System.

La transformation de check-house en Characterization Engine / Test Runner, sans destruction de ses connaissances.

La transformation progressive de /api/lia en façade HTTP mince.

La future séparation world → Repository → D1.

La séparation Domain → ModelGateway → Gemini.

Le système d’Execution Events transversal.

Les règles de dépendances autorisées/interdites.

La correspondance des grands groupes des 86 scripts historiques avec l’architecture cible.

L’ordre de construction, les niveaux de risque et les critères permettant de déclarer une extraction réellement réussie.

Le critère ultime : un nouvel agent doit pouvoir comprendre l’Agence par ses contrats et ses branches, sans devoir lire son histoire.

Et surtout

Nous avons maintenant trois niveaux distincts :

NIVEAU 1

AUDIT

« Qu'avons-nous réellement ? »

↓

NIVEAU 2

RATIONALISATION

« Quelle géométrie devrait avoir le système ? »

↓

NIVEAU 3

TARGET ARCHITECTURE V1

« Quels composants, contrats et frontières allons-nous réellement construire ? »

Nous sommes donc prêts pour la phase suivante : le BUILD MAP — la traduction de cette architecture cible en plan de construction concret, composant par composant, avec pour chacun : origine historique, nouveau nom, responsabilité exacte, contrat, dépendances entrantes/sortantes, niveau R0–R6, ordre de migration, tests à créer et critères de sortie.

C’est ce document qui permettra ensuite de commencer la transformation sans avancer à l’aveugle.
